## Additional Findings Not in Original Audit

### A. Hero is outside `<main>` (semantic HTML issue)

`src/app/page.tsx:19` wraps only `About`, `Projects`, `Skills`, `Contact` in `<main>`.

`Hero` renders before `<main>`, meaning the primary headline and CTA are outside the main landmark.

Google and screen readers use `<main>` to identify the primary content region.

Fix:
Move `<Hero />` inside `<main>` in `page.tsx`.

Priority: MEDIUM

---

### B. Hero component is `"use client"` (SSR/crawl risk)

`src/app/components/Hero.tsx:1` declares `"use client"` due to Framer Motion.

This means the H1 ("Building software that ships.") is **not server-rendered**.

Google can index JS-rendered content but it's a two-pass crawl — slower and less reliable.

Fix options:

Option 1 (easiest):
Extract the text content into a server component wrapper and only wrap the motion animations in a client component.

Option 2:
Use Framer Motion's `LazyMotion` with SSR-safe variants or replace hero animations with CSS transitions to eliminate the client boundary entirely.

Priority: MEDIUM-HIGH

---

### C. No `apple-touch-icon` or web manifest

`public/` has only `favicon.ico`. No 180×180 PNG for iOS home screen saves, no `manifest.json`.

Not a ranking factor but affects trust/polish signals.

Fix:
Add `public/apple-touch-icon.png` (180×180).

In `layout.tsx` metadata:
```ts
icons: {
  apple: '/apple-touch-icon.png',
},
```

Priority: LOW

---

### D. JetBrainsMono font loaded twice

`public/JetBrainsMono-Regular.woff2` exists locally but `layout.tsx:11` loads JetBrains Mono via `next/font/google`.

The local file appears unused (legacy artifact from the refactor).

Fix:
Delete `public/JetBrainsMono-Regular.woff2` — the `next/font` version is already optimal.

Priority: LOW (cleanup)

```ts
import { MetadataRoute } from 'next';

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: 'https://r0tten0x.dev',
      lastModified: new Date(),
      changeFrequency: 'monthly',
      priority: 1,
    },
  ];
}
```

Next.js auto-serves this at `/sitemap.xml` — no static file needed.
